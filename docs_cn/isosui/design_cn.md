# 编辑器与可停靠工作区设计

[English](../../docs/isosui/design.md) · [首次使用](usage_cn.md) · [TODO](todo_cn.md)

**目标：** IsosUI `0.1.0` 配合 IsOS `0.1.0` 和 EOS `0.2.0`。当前编辑器支持 `1.0.0` 图、`@v1.0` 类型及 IsOS 进程 `@v1.1` 类型、类型专用表单、节点集预览、由端口提示推导的频率线型、一个整体浮动核心窗口，以及下述连线检查部分。下文标为**目标**的能力仍需实现。产品版本、图版本、节点 ID、HTTP 路由与模拟器套接字版本分别管理。

## 所有权与数据流

IsOS 拥有已保存图、类型目录、包收据、`/api/isos/v1/node-options`、验证、修订、Apply、管理器状态与统一日志游标。EOS 拥有实时适配器状态、观察、控制与准入。EGIA 拥有代理阶段状态。IsosUI 只保存图草稿、服务器修订、临时选项结果和浏览器本地面板布局。不能从草稿推断已验证包路径、命令权限或实时状态。所有者契约见 IsOS 的 `interfaces/node-graph.md`、`interfaces/releases.md` 和 EOS 的 `interfaces/hardware.md`、`interfaces/control.md`；本页只定义 UI 呈现。

目标 UI 状态为 `{saved_revision, draft, validation, active_revision, catalog, options, readiness, panels}`。编辑更新草稿并使验证结果过期。`Check graph` 请求 IsOS 验证但不写入。`Apply` 发送精确的已保存修订与草稿；冲突时保留本地草稿并展示服务器修订，让操作员明确协调。编辑器可在内存中规范化旧图，但显式 Apply 前不改写已存字节。未知未来图版本只读并报版本错误。UI 版本 `0.1.0` 不代表图 `1.0.0` 已稳定。

## 类型驱动配置与选择器

注册类型提供位置、非空描述、字段与有类型端口；实例提供 ID、标签、描述、设置、包锁定和输入引用。旧包侧车若缺少 `description`，使用 IsOS 的兼容默认，并在 UI 标记为目录默认，而非编造设备描述。每个可见字段从所属契约取得标签、类型、适用单位、用途、默认值与验证帮助；必填空值和单位错误就地显示。

目标设置元数据中的 selector 描述符指定 IsOS 选项来源；本次每项设置只选择一个稳定值。`POST /node-options` 接收当前草稿，响应按节点路径和设置名分组。每个选项包含稳定值、标签、描述、可用性和不可用原因。UI 可按标签、稳定值、描述搜索，支持方向键、Enter、Escape、输入搜索和屏幕阅读器结果数。图只保存稳定 ID，显示标签不进入图。包锁定、依赖设置或图草稿变化时重查；以请求代数忽略过期响应。已选 ID 消失或不可用时，表单保持它并显示警告，阻止 Apply 直到选择有效项。首批选择器是 MuJoCo 场景和设备；同机制以后可支持模型权重等包资源。任意文件路径输入不能代替经过验证的注册选项。

## 连接呈现与编辑

**已实现的连线检查部分。** 当前 Graph 检查器比较来源和目标端口声明的精确类型 ID，并显示两侧 IDL，包括负载字段的 `x-unit` 单位标注。缺少目录描述符时显示元数据不可用，不将连线误标为已拒绝。执行 `Check graph` 后，编辑器把四段连线目标路径映射到 IsOS 展开的诊断指针，只把 `/inputs/<port>/<source-index>` 诊断附在对应连线上，显示代码、路径和消息；多来源输入的端口级诊断保留在完整“诊断”区域。被拒绝的连线有可见线条与无障碍文本。修改、撤销、重做或刷新草稿会清除此验证结果，旧编辑请求的迟到响应会被忽略。检查器将其标为**草稿检查**，另行显示 IsOS 部署状态，并可打开 EOS 监视器查看节点实时健康；Graph 连线本身尚未显示单节点实时健康标记。连线兼容性以精确类型身份为准，UI 不转换负载单位。这一部分尚不包含连线优先级/频率控件、通用资源选择器，或独立的控制/监视/Vision/日志面板。

边是输入上的来源引用。目标可选 `priority` 为 `-20`（最高）到 `19`（最低）的整数，默认 `0`；可选 `frequency_hz` 是有限正数，缺失表示该边无上限。生产者端口的 `expected_rate_hz` 仍只是提示，不是保存的边限频。优先显示实际配置；无边限频时显示 `unlimited`，生产者提示可单独显示。旧来源引用显示优先级 `0`、无限频，但不修改图。只编辑选中的边，保留未知的兼容字段，本地验证即时反馈，Apply 前由 IsOS 再验证。

传输锚点形状、精确负载类型颜色、节点层/组标记、运行故障轮廓、边优先级/频率指示分别编码。目标线型表达配置的限频；实线表示无限频，而非测得高频。线路、检查器和无障碍名称都显示如 `nice 0 · ≤ 20 Hz` 的文本。优先级使用不依赖颜色的标记或线宽等级，提供图例和焦点/悬停详情。当前代码用端口 `expected_rate_hz` 决定线型并用中性色；边元数据可用后需改变这一行为。尚未确认运行时路由的边显示“仅设计”，不暗示已实际传输。

## 面板与页面类型

Home、Graph、配置属于**工作页面**：紧凑对齐、方便扫读、有界滚动、状态上下文持续可见。概览或解释性首页属于**视觉页面**，可用更宽间距和图像。两类页面共享现有 SCSS 主题 token、Island-web 的排版参考、透明或轻微半透明表面；实色填充只用于提高可读性。桌面控件约 28–30 px，触控目标至少 44×44 px。全部控件有可见键盘焦点、禁用与错误状态；状态不能只靠颜色表达。

目标工作区面板（`control`、`monitor`、`vision`、`logs`）各自在浏览器本地存储 `{open, docked, collapsed, x, y, width, height}`，以布局版本和机器人 ID 为键。拖动/调整大小只改几何信息。短暂防抖后保存；加载时拒绝损坏数据、限制在视口内并恢复安全默认布局。停靠不销毁面板内容和订阅。关闭 Vision 断开流，隐藏日志 Follow 暂停轮询，监视轮询有界且不活动时停止。活动修订过期或 API 失联时禁用命令，即使面板重叠也保持错误可见。焦点按最近活动面板排列；Esc 取消拖动/调整大小而不改图。窄屏强制按顺序叠放，保留关键状态和 Stop 控件。

## 首次使用的可观测性算法

打开 Home 时获取设置、包收据、保存/活动修订、进程就绪和全部来源日志第一页。先从管理器响应确定当前运行，再显示最早的就绪或失败事件，之后才使用高级筛选。IsOS 提供时，日志行呈现时间、级别、来源、核心、可选 `node_path`、`event_code`、`run_id`、可选 `correlation_id` 和消息。浏览器错误标记 `browser`，不能冒充服务器来源。游标轮询从最后游标继续，识别轮转并展示新运行边界，不把不同日志流连在一起。首次使用指南按包→图→Apply→就绪→控制→日志→停止的顺序教学。
