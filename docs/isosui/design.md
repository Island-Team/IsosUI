# Editor and dockable workbench design

[中文](../../docs_cn/isosui/design_cn.md) · [First use](usage.md) · [TODO](todo.md)

**Target:** IsosUI `0.1.0` with IsOS `0.1.0` and EOS `0.2.0`. The current editor supports a `1.0.0` graph, `@v1.0` types plus the IsOS process `@v1.1` type, type-specific node forms, node-set previews, frequency patterns derived from port hints, and one combined floatable core window. Everything identified below as **target** still needs implementation. Product versions, graph versions, node IDs, HTTP routes and simulator socket versions are separate identities.

## Ownership and data flow

IsOS owns the saved graph, type catalog, package receipts, `/api/isos/v1/node-options`, validation, revisions, Apply, manager status and unified log cursor. EOS owns live adapter status, observation, control and admission. EGIA owns agent-stage state. IsosUI keeps only a draft graph, server revision, transient option results and browser-local panel geometry. It must never infer a verified package path, command authority or live status from the draft. Read the owner contracts in IsOS `interfaces/node-graph.md` and `interfaces/releases.md` and EOS `interfaces/hardware.md` and `interfaces/control.md`; this page defines their UI projection only.

The target UI state is `{saved_revision, draft, validation, active_revision, catalog, options, readiness, panels}`. Edits update the draft and mark validation stale. `Check graph` asks IsOS to validate without writing. `Apply` sends the exact saved revision and draft; on a conflict, keep both the local draft and server revision visible for explicit reconciliation. The editor normalizes legacy graph forms in memory but does not rewrite stored bytes until explicit Apply. Unknown future graph versions open read-only with a version error. UI version `0.1.0` does not assert graph `1.0.0` stability.

## Type-driven configuration and selector

The registered type supplies placement, a nonblank description, fields and typed ports. The instance supplies ID, label, description, settings, package pin and input references. An old type sidecar without `description` receives the IsOS compatibility fallback; the UI labels it as catalog fallback rather than inventing a device description. Every visible field has label, type, unit where relevant, purpose, default and validation/help text from its owning contract. Empty required values and invalid units are inline errors.

The target selector descriptor on a setting identifies an IsOS option source; this release selects one stable value per setting. `POST /node-options` receives the current draft; the response groups options by node path and setting name. Every option has stable value, label, description, availability and an unavailable reason. The UI search matches label, stable value and description, with keyboard arrows, Enter, Escape, typeahead and a screen-reader count. The selected value is stored by stable ID; display labels never become graph values. Re-query when the package pin, dependent setting or draft graph changes. Ignore stale responses with a request generation counter. If the selected ID disappears or becomes unavailable, keep it in the form with a warning, and block Apply until the operator selects a valid option. The first concrete selectors are MuJoCo scene and device; the same mechanism later handles package assets such as model weights. Arbitrary filesystem entry is not a substitute for a verified registry option.

## Wire projection and editing

An edge is the source reference attached to an input. Target optional `priority` is a signed integer from `-20` (highest) to `19` (lowest), default `0`; optional `frequency_hz` is finite and positive, absent for no edge cap. The producer port's `expected_rate_hz` remains a hint, never a saved edge cap. Render actual configured values first; where no edge cap exists, show `unlimited` and optionally the producer hint separately. For an old source reference, display priority `0` and `unlimited` without mutating the graph. Edit only the selected edge, preserve all unknown compatible fields, validate locally for immediate feedback and ask IsOS to validate before Apply.

Transport anchor shape, exact payload-type color, layer/group node marks, runtime fault outline and wire priority/frequency indicators remain distinct. Target line pattern expresses the configured cap; a solid line means no cap, not a measured high rate. A text label such as `nice 0 · ≤ 20 Hz` accompanies the line and appears in the inspector and accessible edge name. Use a consistent priority marker or stroke tier independent of color, with a legend and focus/hover details. Current code uses port `expected_rate_hz` for patterns and neutral color; that behavior changes when edge metadata is available. Design-only edges show a `design only` badge until a runtime route is confirmed, and do not imply active delivery.

## Panels and page kinds

Home, Graph and configuration are **work pages**: dense, aligned, scannable rows, bounded scrolling and persistent status context. Overview or explanatory landing content is a **visual page** with more spacing and imagery. Both share existing SCSS theme tokens, Island-web typography and transparent or lightly translucent surfaces; solid fill is reserved for legibility. Desktop controls are approximately 28–30 px high and touch hit targets at least 44×44 px. All controls expose focus-visible, disabled and error states; status never depends on color alone.

Target workspace panels (`control`, `monitor`, `vision`, `logs`) each have `{open, docked, collapsed, x, y, width, height}` in browser-local storage, keyed by UI layout version and robot ID. Dragging or resizing modifies only geometry. Persist after a short debounce; on load, reject malformed data, clamp to viewport and restore a safe default. Docking preserves panel content and subscriptions. Closing Vision disconnects its stream; hiding log follow pauses polling; monitor polling is bounded and stops when inactive. A stale active revision or lost API connection disables commands and remains visible even when panels overlap. Focus order follows the last active panel; Esc exits resize/drag without changing the graph. At narrow widths, force a stacked layout with all critical status and Stop controls visible.

## First-use observability algorithm

On opening Home, fetch setup, package receipts, saved/active revision, process readiness and the first page of all-source logs. Identify the current run from the manager response, then show the earliest ready or failure event before advanced filters. A log row presents timestamp, level, source, core, optional `node_path`, `event_code`, `run_id`, optional `correlation_id` and message when IsOS provides them. Browser-only errors remain marked `browser`; never merge them into server provenance. Cursor polling resumes from the last server cursor, detects rotation, and shows a new-run boundary rather than concatenating unrelated streams. The first-use guide teaches package → graph → Apply → readiness → control → logs → stop in that order.
