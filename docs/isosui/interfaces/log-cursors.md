# Current-run log navigation — target P07 UI contract

[中文](../../../docs_cn/isosui/interfaces/log-cursors_cn.md) · [Workbench design](../design-log-cursors.md) · [First use](../usage.md)

**Target, not implemented.** IsOS owns the manager-session ID, deployment-run ID, accepted event order, retention, first-event anchor, opaque cursor, rotation gap and live status. IsosUI presents those owner values. Its local browser console is a separate source of diagnostic text and never supplies an IsOS run, event, PID or readiness claim. The current UI only reads `{lines,next_cursor,rotated}` and cannot guarantee a first event across rotation.

## Selection and ordering

On opening Home Logs, read IsOS status first. The opt-in `GET /api/isos/v1/logs?view=current` response supplies `scope` for the current manager session or deployment run. Before any admitted run, `scope.kind` is `manager_session` and its anchor waits for the first typed package or Apply failure across all accepted sources; a package failure during Run/Restart preflight is eligible, while a Validate-only failure is not. Once a run is admitted, IsOS persists `last_run_id` as `deployment_run` scope through stop, failure, PID loss, active-revision clearing and manager restart; only the next admitted run replaces it. There is no P07 clear endpoint. Its anchor waits for the first retained ready or failure event across all accepted sources. Do not choose scope from PID, active revision or the latest log row. The server anchor is ordered by IsOS's accepted event sequence, not by client timestamp sorting. While `anchor.state` is `pending`, `anchor.event` is null and `lines` is empty; keep polling with the run-bound cursor and show a waiting state. `unavailable` plus `log_anchor_unavailable` means the first event could not be persisted or recovered; show an explicit loss alert instead of waiting forever. Once found, show that anchor before any source, level, node or correlation filter; filtered detail `lines` begin strictly after it, and the anchor stays pinned when the operator narrows the list. A prelaunch failure under the manager session must not be relabeled with an older active run. If no matching event remains, show an explicit unavailable or retention-gap state; do not synthesize one from an unfiltered page.

The default detail stream is the **current** session or run returned in `scope`. The UI requests `view=current` and treats its cursor as opaque. It never decodes or persists a cursor across sessions or deployments. IsOS binds a cursor to `scope`, query and retention generation; a changed run or stale cursor produces a typed diagnostic and bounded same-scope rebase. The UI checks each response scope against its prior scope before displaying rows and refetches status when the scope changes. P07 has no historical-run selector; new-run scope changes produce a visible boundary and a new anchor request.

The opt-in response uses `scope:{kind:manager_session|deployment_run,run_id,active_revision}`, unfiltered `anchor:{kind:first_prelaunch_failure|first_ready_or_failure,state:pending|found|unavailable,event}`, `lines`, `next_cursor`, `rotated` and typed `diagnostics` with `log_run_changed`, `log_cursor_expired`, `log_collector_gap` or `log_anchor_unavailable` plus nullable count. `source`, `level`, `node_path` and `correlation_id` filter only detail `lines`; `anchor` is unchanged. `limit` is 1–200, default 100; IsOS scans at most 64 KiB of retained log bytes per page, so an empty filtered page may still advance the cursor. `GET /api/isos/v1/process-status` adds nullable `run_id` for the last admitted run; it is context for status, not a readiness shortcut. The existing route without `view=current` remains compatible. A legacy IsOS that exposes only `{lines,next_cursor,rotated}` can show retained lines with a compatibility notice, but the UI cannot label its first displayed line as the first event or silently cross a run boundary.

| UI input or owner field | JSON type / unit | UI validation and use |
| --- | --- | --- |
| `view` | literal `current` / — | Required for P07; any other value is an IsOS error. |
| `source`, `level` | source ID or `all`; severity enum / — | Default `all` and `info`; filter detail only. Do not use source/level to select an anchor. |
| `node_path` | canonical saved-graph node JSON Pointer / — | Optional exact filter, at most 512 UTF-8 bytes; reject malformed or member pointers before request. |
| `correlation_id` | ASCII ID / — | Optional exact filter, 1–64 letters, digits, `_` or `-`; never free-text search. |
| `limit` | integer / events | Default 100, range 1–200; clamp UI input before request. |
| `cursor`, `next_cursor` | opaque ASCII string / position | Incoming cursor is at most 512 bytes; pass the returned value unchanged with the same query. Never parse or store across runs; changed filters reset it. Reusing a filter-mismatched cursor returns HTTP 400 `log_cursor_filter_mismatch` at `/query/cursor`; a malformed or tampered cursor returns `log_cursor_invalid` at the same path. The fixed diagnostic omits the token and filter values. |
| `scope` | object `{kind,run_id,active_revision}` / — | Required; `kind` is manager or deployment, ID is 1–64 ASCII bytes, active revision is a digest or null. Identity selects log history, not live health. |
| `anchor` | object `{kind,state,event}` / — | Required; pending/unavailable has null event, found has a complete sanitized P06 event. Pinned above all filters. |
| `lines`, `rotated` | event array; Boolean / — | At most `limit` same-scope events strictly after anchor; `rotated` alone does not mean loss. |
| `diagnostics` | array of `{code,count}` / lost events | Stable code from the four listed above; nonnegative count or null if unknown. Show a persistent accessible notice for loss or run change. |

## Rows, errors and bounds

Each accepted row shows `timestamp` (UTC milliseconds), `level`, `source`, `core`, optional saved-graph `node_path`, stable `event_code`, owner `run_id`, optional `correlation_id`, sanitized `message`, and observed `pid` where available. Render fields as text only; do not render HTML or raw child stderr. The row may expose bounded typed `fields` in a disclosure. A missing field in a legacy row is labeled unavailable, not inferred. IsOS status remains the readiness and stop authority even if the latest event says ready.

One poll is in flight at a time. Request at most 200 rows while IsOS scans at most 64 KiB per page, retain at most 1,000 displayed rows, pause while hidden or Follow is off, and back off repeated failures to at most one request per 30 seconds. Retain the last cursor and rows through a transient collector outage; show a noncolor `role=alert` error and retry. On recovery, recheck status and query identity before resuming. An expired cursor or dropped retained range produces an accessible gap notice with the number/range if IsOS provides it, then resumes from IsOS's bounded same-run position. Never silently clear the gap, replay old lines as new, or fall back to all runs. Reset source/node/correlation detail filters only when the operator asks; they never hide the pinned first-event context. A new run clears prior detail rows and cursor, shows a named boundary, then reads its own first-event anchor from the new current page.

The operator can pause, resume, jump to first event and copy safe IDs. `aria-live=polite` announces a new-run boundary or gap once; streaming rows do not flood announcements. Empty, no matching event, collector unavailable and retention gap have distinct English and Chinese text. The [P07 fixtures](../../../tests/fixtures/log_cursors/README.md) freeze these UI transitions.
