# IsosUI

IsosUI 是公开的 IsOS 配置图编辑器源码，采用 Apache-2.0 许可证。编辑器在本仓库维护；IsOS 提供本地 API，Island-web 托管固定版本的前端构建产物。

## 开发与构建

使用 Node.js 22 和 npm 10 或更新版本：

```bash
npm ci
npm run dev
npm start
npm test
npm run build
```

`npm run dev` 启动开发前端，`npm start` 启动生产模式前端。两者默认监听 `127.0.0.1:16001`，直接请求 IsOS `http://127.0.0.1:16000/api/isos/v2` 和 EOS `http://127.0.0.1:16020/api/eos/v2`。IsOS 启动本地工作台时监管 `npm start`；Ctrl+C 会一并停止前端和 IsOS 服务。可通过 `ISOSUI_PORT`、`ISOSUI_API_ORIGIN=http://127.0.0.1:<API 端口>` 和 `ISOSUI_EOS_API_ORIGIN=http://127.0.0.1:<EOS 端口>` 指定其他环回端口。Webpack 编译时写入 API 地址，并仅接受 HTTP 环回地址。IsOS 和 EOS 必须允许前端的准确来源进行跨域请求。编辑器无需 URL 令牌或 Authorization 请求头。

## 工作台

工作台包含首页、节点图、EOS 和 EGIA 页面。首页可按准确 ID 和版本安装软件包，或链接本地目录并可选提供发布清单的绝对路径；即使节点图尚无软件包节点，也可操作。省略清单路径时，IsOS 会在目录根部查找 `release.json`。首页从 `/packages` 列出所有已安装的软件包记录，并从 `/backends` 单独显示后端就绪状态。首页还显示配置检查、已保存和运行中的修订、进程状态、运行/重启/停止操作及有限长度的日志。EOS 页面仅显示运行中节点图声明的手动、原语与技能节点控制；EGIA 页面仍为预留面板。节点图从 IsOS `/api/isos/v2/node-graph` 读取唯一编写的图，从 `/api/isos/v2/node-types` 读取注册类型目录。节点类型确定核心、层、组、生命周期、配置字段和类型化端口。添加节点会在类型确定的位置创建实例。当前类型定义使用 `@v1.0`；图格式仍为 `2.0.0`，IsosUI 的应用版本独立维护。

节点库通过 IsOS `/node-sets` 显示已安装软件包的节点集。选择节点集并填写字符串参数后，通过 `/node-sets/preview` 预览；服务器返回组合后的图和新增路径，但不会保存。点击添加后，预览结果作为一次可撤销的本地编辑。对于已保存的旧版 MuJoCo 节点图，可显式选择替换；预览会列出将删除的旧仿真、硬件及依赖的控制节点路径，再由用户加入本地草稿。验证和应用仍使用带修订检查的节点图 API。旧版 IsOS 不支持节点集接口时，节点库显示为空。

选择实例后，可编辑标识、标签、描述、能力和类型化设置。后端软件包、版本、场景和设备选项可从 IsOS `/backends` 读取。硬件适配器、坐标系、观测及安全边界通过高级 JSON 编辑。手动和原语节点可选择目标硬件，原语还可选硬件支持的运动模式；技能节点可按顺序选择原语步骤。这些选择会同步调度器引用及类型化观测/状态输入。可搜索类型目录，双击画布添加所选类型，将输出端口拖到类型匹配的输入端口；每个输入只允许一个来源。在画布空白处按住左键拖动可框选多个节点，中键拖动可平移，右键可快捷添加节点或断开连线。Ctrl+Z/Ctrl+Y 撤销或重做图编辑，Delete 删除所有选中节点。验证按图路径显示服务器诊断，应用会先验证再保存修订版本。编辑器有未应用的更改时，首页会禁止运行和重启。刷新前会提示放弃本地更改。画布位置按机器人节点图分别保存在本地浏览器中，不属于节点图数据。桌面控件约 30 像素高，触屏控件至少 44×44 像素。

EOS MuJoCo 进程检查器同时支持软件包提供的 `eos.process.mujoco@v1.0` 类型和旧版后端类型。新类型的场景选项和首页的软件包就绪状态根据 `node.package` 精确版本读取，旧版设置仍可读取。检查器提供“显示 MuJoCo 窗口”设置，在该后端节点的环境变量中写入 `MUJOCO_GUI=1`。应用节点图并启动或重启 EOS 后，窗口显示 EOS 直接监管的仿真实例。关闭此设置时仿真以无界面模式运行。

节点顶部边框颜色标识注册的层，同一层内的确定性明暗色阶标识组（包括 `mujoco` 等软件包组）。进程、硬件、调度器、控制及 EGIA 通用/数据层采用固定色相，其他层根据名称计算稳定色相。组名从五档受限明暗色阶中选择，并分别适配浅色和深色主题。卡片标签显示核心、硬件类型和软件包的准确版本；错误描边和运行状态独立于图身份。端口和连线颜色区分相机数据、观测、运动、请求、结果、健康、状态、上下文和规划。标签与端口形状重复表达这些含义。画布只显示简短配置摘要，不把实时数据负载当作节点设置。

节点图只管理配置，不承载实时相机或运动数据。IsOS 在重启受管进程时启用已保存的修订版本。只有已保存修订与运行中修订一致时，EOS 表单才允许调用。手动和原语调用为节点图声明的目标提供类型化运动数据；技能调用为声明的原语序列提供类型化步骤数据。EOS 验证节点身份、模式、限制和调度器路径。手动停止与技能取消也经由这些节点。监视器仅显示 EOS 已发现且节点图已声明的硬件，每 2 秒读取适配器状态、健康和观测，抓取一台选中相机 RGB8 画面的频率不超过 1 Hz 或相机配置的最大频率。适配器状态决定实时、已停止、启动中、故障和过期标记；健康仍单独显示。轮询失败时保留最近的观测，显示错误和观测更新时间。相机卡片不显示观测字段。画面在 Canvas 中解码，限制为 2048×1536、200 万像素、8 MB 解码数据及相机配置的负载上限；超过 5 秒未更新的遥测显示为过期。页面不可见或节点图未运行时停止轮询。

两个构建目录都包含 `index.html`、`assets/`、`IslandTeam.png` 和 `manifest.json`。清单包含 UI 版本、源码提交、构建目标和 IsOS API v2 版本。npm 服务在本机提供 `/en/isos` 与 `/cn/isos`；Island-web 在对应路径提供托管 HTML，并把资源放在 `/isosui/`。

手动发布工作流从现有的 `v<package version>` 标签构建两个压缩包与 `SHA256SUMS`。普通开发和固定提交构建不需要发布版本。
